No production deployment was made while preparing this package.

Back up and verify database AND uploads first. Test on an isolated staging copy with protected data. Preserve live environment, secrets and VAPID keys; do not seed, reset or copy staging DB over production. Migration adds nullable cost snapshot columns and a reservation quantity column to order_items; it does not recompute or change historic totals. A database backup and a tested rollback plan are essential; reverting code alone does not remove schema changes.

Cost workflow: fabric metres and tailoring rate are PER PIECE; multiplied by piece quantity for totals. Workshop has a default rate per piece, editable for a specific order piece. Additional manual cost lines are per piece and ADD to, rather than replace, production costs. Saving production snapshots fabric and workshop rates, so later catalogue price edits do not automatically rewrite existing costs. On editing a legacy order the current fabric price and entered/default workshop rate will be used: verify those amounts before saving. Adding or editing manual lines preserves the existing base total. Legacy totals are NOT automatically reclassified; the report identifies them as unclassified instead of guessing past rates. For legacy stock reservations the first production edit interprets the prior non-manual reservation using the previous one-piece behavior, and reserves quantity x metres thereafter: verify inventory on staging and reconcile old stock before rollout.

Reports: period based on order creation date, excludes cancelled orders and orders with unpriced custom designs. Order-period totals and expense/payment dates have different definitions in existing period report; the item table lists sales before order discounts/shipping, and difference excludes general expenses. Report shows material, workshop, manual lines, legacy/other totals, per-order detail and workshop comparisons. Tailoring per metre = tailoring cost / recorded fabric metres for classified workshop pieces only: an explanatory indicator, NOT an extra fee, and can be misleading across different designs. Missing fabric metres make this ratio unavailable. Owner access only. Data can be incomplete; report does not infer missing or historical components.

On isolated staging test a mixed order, multiple quantities, stock before/after repeat saves, old manual-only and old production records, changes of fabric/workshop, zero and decimal rates, unpriced orders, owner/staff access, status/cost reports, actual device notifications, and all live integrations. Test changing fabric prices after snapshot. Browser cache may require a fresh tab after deployment. Existing Android apps are not changed; web push delivery on a real phone has not been verified.
