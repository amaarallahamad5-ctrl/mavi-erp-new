# دليل التحقق قبل النشر والنسخ الاحتياطي والاستعادة والتراجع (MAVI ERP — `office-*`)

> **تنبيه إلزامي:** هذا الدليل للتنفيذ اليدوي المعتمد من المالكة فقط بعد استيفاء كافة البوابات أدناه. لا يجوز دمج أي كود في `main` أو نشره على الموقع الحي أو لمس قاعدة بيانات الإنتاج أو توصيل مفاتيح مزودات خارجية دون قرار صريح ومستقل.

---

## 1. بوابة التحقق من بناء صورة Docker واستهلاك الحاوية (على جهاز يتوفر به Docker)

داخل الحاوية الحالية لتطوير الكود لا تتوفر خدمة `dockerd`؛ لذلك تم التحقق آلياً من عقد `Dockerfile` و`.dockerignore` وقياس ذروة الذاكرة الفعلية للعملية (`VmHWM < 120 MiB` تحت `NODE_OPTIONS=--max-old-space-size=64`). قبل أي نشر حقيقي يلزم تنفيذ الأوامر التالية على جهاز أو بيئة CI بها Docker:

```bash
docker build -t mavi-erp:staging-check .

# تشغيل معزول بحد ذاكرة صريح 128m مطابق لحاوية الاستضافة الاقتصادية
mkdir -p /tmp/mavi-docker-vol
docker run --rm -d \
  --name mavi-staging-smoke \
  --memory=128m --memory-swap=128m \
  -p 3100:3000 \
  -v /tmp/mavi-docker-vol:/data \
  -e NODE_ENV=production \
  -e MAVI_STAGING_MODE=1 \
  -e AUTO_SEED=0 \
  -e SHOW_OTP=0 \
  -e INITIAL_ADMIN_EMAIL="owner@mavi.eg" \
  -e INITIAL_ADMIN_PASSWORD="ضعي-كلمة-مرور-خاصة-١٦-حرفا-على-الأقل" \
  mavi-erp:staging-check

# فحص الصحة وبوابة العزل واستهلاك الذاكرة الفعلي للحاوية
curl -i http://127.0.0.1:3100/healthz
curl -i http://127.0.0.1:3100/
docker stats --no-stream mavi-staging-smoke
docker stop mavi-staging-smoke
```

**معيار القبول:**
- `/healthz` يعيد `200 OK`.
- `/` و`/store/` يعيدان `401` مع `X-Robots-Tag: noindex, nofollow, noarchive, nosnippet`.
- عدم حدوث `OOMKilled` وبقاء استهلاك الحاوية ضمن حد `128 MiB`.
- حذف `INITIAL_ADMIN_PASSWORD` من إعدادات الاستضافة فور إنشاء حساب المالكة لأول مرة.

## 2. بوابة بيئة Staging المعزولة (قبل أي مساس بالإنتاج)

1. **قاعدة بيانات منفصلة تماماً:** يجب أن تستخدم بيئة Staging قرصاً وملف `DB_PATH` منفصلين كلياً عن قاعدة الإنتاج، ولا تُربط أبداً بقرص الإنتاج.
2. **ضبط متغيرات البيئة في Staging:**
   - `NODE_ENV=production`
   - `MAVI_STAGING_MODE=1` *(يفعّل بوابة تسجيل الدخول الإلزامية، ويعطل إرسال الرسائل/الإشعارات وبكسلات التتبع)*
   - `AUTO_SEED=0`
   - `SHOW_OTP=0`
   - بدون إضافة `OPENROUTER_API_KEY` (العامل الخلفي متوقف افتراضياً `disabled`).
3. **التحقق من HTTPS والكوكيز:** التأكد من عمل الرابط عبر `https://` وظهور خصائص `Secure; HttpOnly; SameSite=Lax` على كوكي الجلسة.

## 3. إجراء النسخ الاحتياطي الإلزامي قبل أي تحديث

1. من حساب المالكة في لوحة الإدارة: افتحي قسم **«النسخ والأمان»** واضغطي تنزيل النسخة الاحتياطية (`GET /api/admin/system/backup`).
   - يستخدم هذا المسار واجهة `SQLite Online Backup API` لالتقاط لقطة متسقة شاملة تغييرات `WAL` والصور المحفوظة دون إيقاف القاعدة.
2. تحققي محلياً من سلامة الملف المنزّل قبل أي خطوة تالية:
   ```bash
   sha256sum mavi-backup-*.db
   sqlite3 mavi-backup-*.db "PRAGMA integrity_check; PRAGMA foreign_key_check; SELECT COUNT(*) FROM orders;"
   ```
   يجب أن تكون النتيجة `ok` وصفر أخطاء مفاتيح أجنبية ومطابقة لعدد الطلبات الفعلي.
3. احتفظي بنسختين منفصلتين من ملف النسخة الاحتياطية وبصمته (`SHA-256`) خارج الخادم.

## 4. إجراء الاستعادة الآمنة (`MAVI_RESTORE_MODE=1`)

خدمة الاستعادة في `src/migration-import.js` مصممة بحيث **لا تفتح ولا تستبدل** ملف القاعدة الحالي (`mavi.db`) أبداً، بل تفحص النسخة المرفوعة وتضعها في ملف جديد مستقل باسم `mavi-restored.db`:

1. اضبطي مؤقتاً في الاستضافة:
   - `MAVI_RESTORE_MODE=1`
   - `MAVI_RESTORE_SECRET` *(رمز عشوائي سري لا يقل عن 32 حرفاً/بايت)*
2. افتحي الرابط الرئيسي، وارفعي ملف `.db` مع الرمز السري لمرة واحدة حتى تظهر رسالة تأكيد الحفظ والفحص (`ok`).
3. حوّلي `DB_PATH` ليشير إلى `/data/mavi-restored.db`، وألغي `MAVI_RESTORE_MODE` و`MAVI_RESTORE_SECRET`، ثم أعيدي تشغيل الخدمة وتحققي من الطلبات والتقارير.

---

## 5. خطة التراجع الفوري (`Rollback`)

- **التراجع الفوري للكود (Code Rollback):**
  جميع جداول المرحلة الأولى (`office_cases`, `office_case_events`, `office_jobs`, `office_job_audit`) مستقلة تماماً ولا تضيف قيوداً عكسية أو Triggers على جداول الطلبات أو المدفوعات أو المخزون. في حال الحاجة لإرجاع الكود إلى إصدار `main` السابق (`995104c`)، يعمل الكود السابق مباشرة على نفس ملف قاعدة البيانات دون تعطل شاشات الطلبات أو الحسابات.
- **التراجع الكامل للبيانات والكود (Full Point-in-Time Rollback):**
  في حال الرغبة في العودة لحالة البيانات الدقيقة قبل الترقية، تُرفع النسخة المحفوظة قبل الترقية عبر `MAVI_RESTORE_MODE=1` إلى ملف جديد منفصل ويُوجَّه `DB_PATH` إليها مع إبقاء الملف السابق محفوظاً للمراجعة وعدم حذفه.
